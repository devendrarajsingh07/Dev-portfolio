A desktop home for a trading journal.

A Java Swing application bringing trade entry, record management, summary reporting, and CSV export into a local desktop workflow.

Java desktop · Trading journal
Engineering focus
Swing interfaces, JDBC persistence, and reusable trade logic
Technology
Java · Swing · JDBC · SQL · CSV · Alpha Vantage

The problem

A journal needs to preserve more than an entry and exit price. Symbols, position side, quantity, date, strategy, and remarks help make a record understandable later. The desktop project brings those fields together with editing, summary statistics, and exports in a single application.

The approach

Swing frames handle login, the dashboard, entry forms, and record views. A Trade model represents journal entries, while TradeDAO uses JDBC prepared statements to read and write database records. Separate services handle CSV export and external market-price requests.

  1. Open the login window
  2. Enter a trade
  3. Persist its journal fields
  4. Review and edit records
  5. Refresh summaries or export CSV

Key decisions

Separate windows from database access

Dashboard and form classes handle the desktop interactions, while TradeDAO contains SQL operations. The Trade model carries journal fields between the interface and persistence layer.

The tradeoff. The separation clarifies responsibilities, but database and network work still need careful scheduling to keep Swing's interface responsive.

Reuse records across summaries and exports

The dashboard reads trade records for totals, winning/losing counts, and buy/sell summaries, and passes records to a CSV export utility. This keeps the stored journal central to several views.

The tradeoff. Refreshing summaries from a record list is straightforward for a small journal, but larger datasets may need database-side aggregation and pagination.

Isolate external quote requests

MarketPriceService contains symbol encoding, HTTP timeouts, response parsing, and provider-error handling. The quote integration is separate from the trade model and entry windows.

The tradeoff. The committed service contains an API-key placeholder and requires configuration; external quote availability cannot be assumed.

Where it stands

The source contains login, trade-entry and editing windows, database-backed records, dashboard summaries, CSV export, and a market-price adapter. It also provides the desktop foundation for the later web version of the journal.

Current scope

The repository README is empty, so this case study is based on the Java implementation. The desktop application was not launched during this review. Login is present, but tenant isolation, production security, and live quote access are not established by this source review.

A useful next iteration would add reproducible setup instructions, move configuration outside source files, and test database failures and UI responsiveness during quote requests.
