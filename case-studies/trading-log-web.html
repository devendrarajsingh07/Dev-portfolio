Taking a trading journal into the browser.

A full-stack adaptation of a desktop trade-recording workflow, combining editable records, search, summary analytics, and export.

Explore the story View source
Project
Full-stack web · Desktop-to-web migration
Engineering focus
REST APIs, relational persistence, and responsive workflows
Technology
React · Node.js · Express · MySQL · Chart.js · JWT

The problem

The desktop journal established a way to record and review trades, but its interface and installation were tied to a local Java application. The web version translates those tasks into browser routes and API operations while retaining the journal's core record fields, summary views, and exports.

The approach

React and Vite provide the browser interface, with an Express API and MySQL persistence behind it. The application includes JWT-based login, trade CRUD, search and filters, profit/loss summaries, Chart.js visualization, CSV downloads, and an Alpha Vantage price endpoint.

  1. Sign in
  2. Record or edit a trade
  3. Search the journal
  4. Review profit/loss summaries
  5. Export records for review

Key decisions

Translate desktop actions into API operations

Adding, viewing, editing, and deleting records become explicit REST endpoints. The browser can present responsive routes while the server owns database queries and response handling.

The tradeoff. A browser deployment introduces authentication, network failures, and server configuration that the local interface did not need to present in the same way.

Keep summaries close to stored records

The trade controller calculates aggregate counts and profit/loss summaries in SQL. Search uses bound parameters for symbols, strategy text, remarks, and side filters.

The tradeoff. Summary correctness still depends on consistent trade data and profit/loss conventions, especially around open positions and buy/sell direction.

Keep records portable

A server-side CSV endpoint exports stored journal fields, while a separate price endpoint connects to Alpha Vantage. The journal therefore supports both in-app review and inspection outside the dashboard.

The tradeoff. External quotes depend on provider availability and quotas; exporting a record does not validate its financial interpretation.

Where it stands

The repository documents a browser-based journal covering login, trade maintenance, filters, analytics, and export. It makes the evolution from a desktop workflow to a client/API/database application visible.

Current scope

This is a trade-recording and analysis project, not order execution or investment advice. JWT login alone does not establish per-user record isolation; the reviewed trade queries operate on the shared trades table. No financial-performance claim is made.

The next engineering step would be explicit record ownership and authorization tests, followed by tests for open positions, side-aware profit/loss calculations, and unavailable quote data.
