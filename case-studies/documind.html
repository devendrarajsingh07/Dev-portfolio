DocuMind / Case study03 — 09

From PDFs to answers you can inspect.

A document workspace combining structured extraction, OCR, retrieval, and conversation with citations back to selected PDFs.

The problem

A useful PDF assistant needs more than a chat box. Scanned pages may need OCR, extraction can miss content, long documents need searchable chunks, and users need to check where an answer came from. Processing also has to survive slow inference and retries without mixing one user's documents with another's.

The approach

DocuMind separates the browser workspace, account/document API, and Python inference service. Next.js provides document preview and chat; Express handles authentication, ownership, conversations, and jobs; FastAPI performs extraction and retrieval. PostgreSQL stores durable application records, while Qdrant indexes document chunks and Redis supports provider coordination and encrypted caches.

  1. Upload and validate a PDF
  2. Extract text or run OCR
  3. Chunk, embed, and index
  4. Retrieve and rerank evidence
  5. Generate an answer with citations

Key decisions

Preserve the original reading

Native PDF text is preserved alongside page-level OCR structure. Optional image enhancement is checked against the original reading and can fall back when content is lost or numeric fields change.

The tradeoff. Those preservation checks are heuristics. OCR confidence and a cleaner image do not prove transcription accuracy.

Retrieve within an explicit document boundary

Retrieval is filtered by owner and selected documents, followed by cross-encoder reranking and bounded context. Answers include normalized citations so the reader can return to supporting pages.

The tradeoff. Retrieval and citations make answers inspectable, but users still need to verify important statements against the original PDF.

Persist work beyond a single HTTP request

PostgreSQL-backed jobs use idempotency keys, leases, and progress state. Matching retries reuse the existing job; Redis coordinates budgets and caching rather than serving as the authoritative job store.

The tradeoff. Job recovery adds complexity, and files, vectors, provider calls, and database changes do not share one distributed transaction.

Where it stands

The documented workspace supports authenticated document upload, PDF preview, page-level analysis, reindexing, selected-document chat, and job-status feedback. The implementation connects the complete document-to-answer workflow rather than treating extraction and chat as separate demos.

Current scope

Extraction summaries are not guaranteed comprehensive reports. OCR confidence is not measured transcription accuracy, optional enhancement needs trusted document-trained weights, and local service health does not establish public-production readiness. No answer-accuracy or latency benchmark is claimed here.

The next evaluation would use a labeled document set to measure extraction errors, retrieval relevance, and whether citations actually support generated answers.
